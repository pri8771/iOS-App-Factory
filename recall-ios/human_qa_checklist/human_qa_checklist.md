## Original Prompt

```
Build a polished, fully offline iOS spaced-repetition flashcard app called "Recall". Native Apple stack ONLY: SwiftUI + SwiftData for persistence, Swift Charts for stats. No backend, no accounts, no third-party SDKs, no network of any kind — the app must work in airplane mode forever, all data on-device. Follow the ios-app-factory-rules. Runnable in the iOS Simulator via Xcode; provide clear run instructions.

HARD RULE ON GAPS: Anything that would need infrastructure this project cannot provide (cloud sync, shared/community decks, a deck marketplace) must NOT be faked or stubbed. Record each honestly as a gap with a short note on what building it for real would take. Do not add placeholder UI that pretends these work.

CORE FEATURES (favor complete over broad):
1. Decks & cards: create/edit/archive decks; cards have a front, back, and optional note. Card editing must be fast and keyboard-friendly.
2. Spaced-repetition scheduling: implement the SM-2 algorithm (ease factor, interval, repetition count) with Again/Hard/Good/Easy grading. THIS IS THE HEART OF THE APP. Implement it as its own standalone, pure, tested module — provably right, not plausibly right. Unit tests MUST cover: first reviews, lapses resetting the interval, ease-factor floors, and day-boundary handling in the device's local time zone (a "day" is a calendar day).
3. Review session: shows due cards for a chosen deck (or all decks); front → tap to reveal → grade. Session summary at end (cards reviewed, again-rate, time spent). Must handle interruption gracefully — quitting mid-session loses nothing.
4. Stats: per-deck and overall — due-forecast bar chart for next 30 days, daily review-count history, and retention rate (% graded Good/Easy). Handle empty and sparse data gracefully.
5. Deck import/export: export any deck to CSV; import cards from a two-column CSV (front, back) with a preview step and per-row error reporting — never silently drop a row.
6. Review reminders: one optional LOCAL notification per day ("You have N cards due") at a user-chosen time; respect permission denial gracefully. No push, no server.

PRIORITIES (in order): (1) SM-2 module correctness above all — proven via its tests; (2) review-flow speed; (3) honest empty states. Include a "demo data" toggle in Settings that seeds two decks with a realistic review history so stats screens are never empty on first look.
```

**Recall — Manual QA Checklist** (Xcode 16+, iOS 17+ simulator or device; run in this order)

### 0. Before you start
- Fresh install, all system settings default, Wi-Fi/cellular *on* for now (airplane-mode pass comes later).
- Note whether you're on **Simulator** or a **physical device** — write this down, because the haptic-ladder check below is only meaningful on a real device.
- Keep this open on a second screen; check off each expected result as you go, screenshot anything that deviates.

### 1. Launch & onboarding
- Launch from a clean install.
  - **Expect:** brief loading state, then lands on the **Study** tab. No blank white screen, no infinite spinner.
- If a data-recovery/error screen ever appears (corrupted store), confirm it's readable and offers a real retry/start-fresh action, not a crash loop.

### 2. Study tab — empty states (test both, they're different messages)
- On first launch with zero decks: **expect** a true "no decks yet" empty state — icon, one-line explainer, an "Add deck" action. Not a blank list.
- Create one deck, add zero cards, look at Study tab again: **expect** the deck shows 0 due, and if you tap into it with no due cards, you should see a distinct **"all caught up"** state — this is a different message from true-empty, and both need to exist and read differently.

### 3. Deck & card management
- Tap "Add deck," try saving with a blank name → **expect** save is blocked with visible validation.
- Save a valid deck name → **expect** it appears in the list immediately, tappable, due count starts at 0.
- Open the deck, add a card using only the keyboard (type front, tab/return to back, tab/return to note, return to save) → **expect** fast, no mouse/tap needed between fields, card appears immediately.
- Try saving a card with an empty front or back → **expect** validation blocks it and preserves your typed text (nothing is silently discarded).
- Add a second card with the exact same front+back as an existing one → note whatever the in-app behavior is (this is mainly exercised through CSV import; in the editor it may simply save — that's fine, duplicate *detection* is a CSV-import concept, not a live-editor block).
- Delete a card → **expect** it disappears from the deck, and if this deck already has review history, check the deck's stats afterward — retention/history should visibly shift. That's expected honest behavior (cascading deletion of that card's review log), not a bug.
- Archive a deck (if the control is present) → **expect** it drops out of Study/active review lists. Then go re-add cards up toward the Free-tier cap (3 decks / 300 cards) and confirm the archived deck's cards still count against the cap rather than letting you sneak past it.

### 4. Review session — the core loop
- With at least 2 cards due in one deck, start review.
  - Tap/reveal the card → **expect** a fast (<200ms-feeling), no-bounce settle, not a slow 3D flip.
  - Grade a card Again, then another Hard, Good, Easy across your available cards → **expect** the queue updates immediately after each grade and a graded card never reappears as due again in the same session.
  - Confirm grading is readable **without color**: switch the device/simulator to Grayscale (Settings → Accessibility → Display & Text Size → Color Filters → Grayscale, or Smart Invert) and confirm you can still tell Again/Hard/Good/Easy apart by shape/position/label alone.
  - Finish the whole queue → **expect** a session summary (cards reviewed, again-rate, time spent) appears **only** after true completion — never partway through.
  - Exit mid-session deliberately (there should be an explicit "End session" control) → **expect** its copy says something like "your progress is saved," not a loss-warning dialog — and confirm graded cards really are still graded when you come back.

### 5. Force-quit interruption test — the single most important check in this app
This currently can't be verified by the automated test suite: `ReviewSessionViewModelTests.swift` is failing to compile (a real main-actor-isolation error on a `(plan:service:...)` initializer per the latest build verification), so the scripted `XCUIApplication.terminate()` test cannot run right now. Until that's fixed, this manual procedure is the *only* proof this claim holds. Do it exactly:
1. Create a fresh deck, add exactly 2 cards.
2. Start a review session for that deck.
3. Reveal and grade the **first** card (any grade).
4. Within about a second of grading (don't wait), force-quit the app from the app switcher (swipe it away).
5. Relaunch the app, go to that deck.
6. **Expect:** exactly 1 card still due (the ungraded one). The graded card is gone from the due stack. No fabricated/partial session summary ever appeared. No crash on relaunch.
- Repeat once more, but this time kill the app a beat *earlier* (right as you tap the grade button, before the reveal settles) to probe the boundary. Same expectation: never lose data, never double-count.

### 6. Study All / multi-deck
- With 2+ decks each having due cards, start "Study All."
  - **Expect:** cards are pulled from all due decks into one session, and the same interruption-safety behavior from Section 5 holds (repeat a quick force-quit here too if time allows — multi-deck is where a live-query bug would most likely surface as reordering).
- Background the app for 10+ seconds mid-browse (not mid-session), return.
  - **Expect:** due counts refresh, no stale numbers, no crash.

### 7. Stats
- Fresh install, no reviews yet: open Stats.
  - **Expect:** explicit empty state, no fabricated/flat placeholder chart.
- After a handful of reviews: reopen Stats.
  - **Expect:** a distinct **sparse-data** state (not the same copy as full-empty, not a crash) — the 30-day forecast chart and history should reflect only real data.
- Do enough reviews to get real numbers, check per-deck drill-down.
  - **Expect:** retention shows an actual percentage; if a deck has zero graded reviews, retention should show a "not enough data" state, never a fabricated 0%.
- Day-boundary check: change the device clock (or just wait) across a local midnight, reopen the app.
  - **Expect:** due list updates for cards whose due date is now today; nothing stays stuck on yesterday's stack.
- If you can safely change the device's timezone: do it, reopen app.
  - **Expect:** due status can legitimately shift purely from the timezone change (this is documented, expected behavior — check the Gap & Limitations screen mentions it), and nothing crashes.

### 11. Subscription / Plan (currently absent — confirm it stays honest)

  - **Expect:** if it's not present, that's the current state — confirm there's no disabled/greyed-out "Upgrade" control anywhere implying a paywall exists. ### 13. Offline / Airplane Mode

**Recall — Manual QA Checklist** (Xcode 16+, iOS 17+ simulator or device; run in this order)

### 0. Before you start
- Fresh install, all system settings default, Wi-Fi/cellular *on* for now (airplane-mode pass comes later).
- Note whether you're on **Simulator** or a **physical device** — write this down, because the haptic-ladder check below is only meaningful on a real device.
- Keep this open on a second screen; check off each expected result as you go, screenshot anything that deviates.

### 1. Launch & onboarding
- Launch from a clean install.
  - **Expect:** brief loading state, then lands on the **Study** tab. No blank white screen, no infinite spinner.
- If a data-recovery/error screen ever appears (corrupted store), confirm it's readable and offers a real retry/start-fresh action, not a crash loop.

### 2. Study tab — empty states (test both, they're different messages)
- On first launch with zero decks: **expect** a true "no decks yet" empty state — icon, one-line explainer, an "Add deck" action. Not a blank list.
- Create one deck, add zero cards, look at Study tab again: **expect** the deck shows 0 due, and if you tap into it with no due cards, you should see a distinct **"all caught up"** state — this is a different message from true-empty, and both need to exist and read differently.

### 3. Deck & card management
- Tap "Add deck," try saving with a blank name → **expect** save is blocked with visible validation.
- Save a valid deck name → **expect** it appears in the list immediately, tappable, due count starts at 0.
- Open the deck, add a card using only the keyboard (type front, tab/return to back, tab/return to note, return to save) → **expect** fast, no mouse/tap needed between fields, card appears immediately.
- Try saving a card with an empty front or back → **expect** validation blocks it and preserves your typed text (nothing is silently discarded).
- Add a second card with the exact same front+back as an existing one → note whatever the in-app behavior is (this is mainly exercised through CSV import; in the editor it may simply save — that's fine, duplicate *detection* is a CSV-import concept, not a live-editor block).
- Delete a card → **expect** it disappears from the deck, and if this deck already has review history, check the deck's stats afterward — retention/history should visibly shift. That's expected honest behavior (cascading deletion of that card's review log), not a bug.
- Archive a deck (if the control is present) → **expect** it drops out of Study/active review lists. Then go re-add cards up toward the Free-tier cap (3 decks / 300 cards) and confirm the archived deck's cards still count against the cap rather than letting you sneak past it.

### 4. Review session — the core loop
- With at least 2 cards due in one deck, start review.
  - Tap/reveal the card → **expect** a fast (<200ms-feeling), no-bounce settle, not a slow 3D flip.
  - Grade a card Again, then another Hard, Good, Easy across your available cards → **expect** the queue updates immediately after each grade and a graded card never reappears as due again in the same session.
  - Confirm grading is readable **without color**: switch the device/simulator to Grayscale (Settings → Accessibility → Display & Text Size → Color Filters → Grayscale, or Smart Invert) and confirm you can still tell Again/Hard/Good/Easy apart by shape/position/label alone.
  - Finish the whole queue → **expect** a session summary (cards reviewed, again-rate, time spent) appears **only** after true completion — never partway through.
  - Exit mid-session deliberately (there should be an explicit "End session" control) → **expect** its copy says something like "your progress is saved," not a loss-warning dialog — and confirm graded cards really are still graded when you come back.

### 5. Force-quit interruption test — the single most important check in this app
This currently can't be verified by the automated test suite: `ReviewSessionViewModelTests.swift` is failing to compile (a real main-actor-isolation error on a `(plan:service:...)` initializer per the latest build verification), so the scripted `XCUIApplication.terminate()` test cannot run right now. Until that's fixed, this manual procedure is the *only* proof this claim holds. Do it exactly:
1. Create a fresh deck, add exactly 2 cards.
2. Start a review session for that deck.
3. Reveal and grade the **first** card (any grade).
4. Within about a second of grading (don't wait), force-quit the app from the app switcher (swipe it away).
5. Relaunch the app, go to that deck.
6. **Expect:** exactly 1 card still due (the ungraded one). The graded card is gone from the due stack. No fabricated/partial session summary ever appeared. No crash on relaunch.
- Repeat once more, but this time kill the app a beat *earlier* (right as you tap the grade button, before the reveal settles) to probe the boundary. Same expectation: never lose data, never double-count.

### 6. Study All / multi-deck
- With 2+ decks each having due cards, start "Study All."
  - **Expect:** cards are pulled from all due decks into one session, and the same interruption-safety behavior from Section 5 holds (repeat a quick force-quit here too if time allows — multi-deck is where a live-query bug would most likely surface as reordering).
- Background the app for 10+ seconds mid-browse (not mid-session), return.
  - **Expect:** due counts refresh, no stale numbers, no crash.

### 7. Stats
- Fresh install, no reviews yet: open Stats.
  - **Expect:** explicit empty state, no fabricated/flat placeholder chart.
- After a handful of reviews: reopen Stats.
  - **Expect:** a distinct **sparse-data** state (not the same copy as full-empty, not a crash) — the 30-day forecast chart and history should reflect only real data.
- Do enough reviews to get real numbers, check per-deck drill-down.
  - **Expect:** retention shows an actual percentage; if a deck has zero graded reviews, retention should show a "not enough data" state, never a fabricated 0%.
- Day-boundary check: change the device clock (or just wait) across a local midnight, reopen the app.
  - **Expect:** due list updates for cards whose due date is now today; nothing stays stuck on yesterday's stack.
- If you can safely change the device's timezone: do it, reopen app.
  - **Expect:** due status can legitimately shift purely from the timezone change (this is documented, expected behavior — check the Gap & Limitations screen mentions it), and nothing crashes.

### 8. Demo Data (currently a gap, not a feature — test it as a gap)
- Open Settings → Demo Data.
  - **Expect:** this is not yet a real seeding feature. Confirm the screen honestly says so (no fake toggle that appears to work but does nothing). If you find an actual working toggle, flag that as new — it wasn't part of prior verified builds.

### 9. CSV export / import (currently a gap, not a feature — test it as a gap)
- Open Settings → CSV Export and CSV Import.
  - **Expect:** both currently route to an honest "not yet available" placeholder screen — confirm the copy is clear and doesn't imply the feature works. There should be no button that looks functional but silently does nothing.
  - If either is actually wired up in the build you're testing, then run the real check instead: export a deck, re-import it, and separately try importing a hand-made CSV with a blank front, a blank back, a wrong column count, an embedded comma/quote, a duplicate row, and a CRLF line ending — **expect** every bad row gets its own distinct, visible reason in a preview before you commit, nothing vanishes silently.

### 10. Reminders (currently a gap, not a feature — test it as a gap)
- Open Settings → Reminders, toggle on, grant/deny the system permission prompt, pick a time.
  - **Expect:** the toggle/permission/time-picker UI works and saves your preference. **Do not expect an actual notification to fire** — there is no notification-scheduling service behind this yet. Confirm the UI doesn't claim otherwise (no "Scheduled!" confirmation implying a real notification will arrive).
  - Deny permission on a fresh install → **expect** a clear, non-crashing fallback message, not a dead end.

### 11. Subscription / Plan (currently absent — confirm it stays honest)
- Look through Settings for any Plan/Subscription screen.
  - **Expect:** if it's not present, that's the current state — confirm there's no disabled/greyed-out "Upgrade" control anywhere implying a paywall exists. If a paywall UI does exist in your build, confirm it links to privacy policy/terms, shows a bounded error (not an infinite spinner) if purchase is attempted offline, and includes Restore Purchases.

### 12. Gap & Limitations screen
- Open it from Settings.
  - **Expect** it explicitly discloses: the StoreKit-purchase network exception, notification staleness ("never created" framing for skipped days), timezone-crossing due-date flips, and iCloud backup/restore divergence across devices. If any of these strings are missing, that's a finding.

### 13. Offline / Airplane Mode
- Turn on Airplane Mode. Repeat: create a deck, add cards, run a full review session, view stats.
  - **Expect:** everything above works identically with zero network spinners or error popups. The app must never hang waiting on a network call for any core-loop action.

### 14. Accessibility pass
- VoiceOver on: walk through deck creation, grading, and stats — **expect** every control has a meaningful spoken label, nothing is an unlabeled icon in the critical path.
- Dynamic Type at largest accessibility size: **expect** card text scrolls, grade buttons stay visible/reachable (pinned to the bottom safe area), nothing clips or overlaps.
- Reduced Motion on: **expect** the reveal-settle animation is toned down/removed, but haptics and state changes still communicate progress.
- Haptic ladder (**physical device only** — simulators don't produce real haptics, don't mark this "pass" from a simulator): grade Again/Hard/Good/Easy in sequence and confirm you can feel an ascending intensity, ending with Easy feeling distinctly "extra."

### 15. Persistence / regression pass
- Across several sessions (add cards, grade, force-quit, relaunch, repeat 3-4 times): **expect** no duplicate sessions, no lost cards, no drift between what's shown and what's actually due.
- Re-run Section 5 (force-quit) after any future change to the review session or data layer — it's the one regression check that should never be skipped.
- Re-run the CSV/demo-data/reminders gap checks after any Settings change, to confirm the app hasn't quietly started claiming a feature works before it actually does.

### Known gaps to record as expected current state, not new bugs
- Reminder notifications: preference is saved; nothing is actually scheduled (no `ReminderScheduler` exists yet).
- CSV import/export: parser exists and is well-tested internally, but Settings UI currently routes to an honest placeholder.
- Demo Data toggle: not yet a real seeding feature.
- Subscription/StoreKit/Plan screen: not implemented.
- Automated interruption test (`ReviewSessionViewModelTests.swift` / the XCUITest suite): currently fails to compile due to a main-actor-isolation error — Section 5's manual procedure is the only current proof of interruption-safety until that's fixed.
- SM-2 external-reference cross-check and an explicit DST-transition test are still absent from the automated suite (day-boundary and timezone-crossing behavior are covered; DST specifically is not).
