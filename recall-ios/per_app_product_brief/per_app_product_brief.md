```
Build a polished, fully offline iOS spaced-repetition flashcard app called "Recall". Native Apple stack ONLY: SwiftUI + SwiftData for persistence, Swift Charts for stats. No backend, no accounts, no third-party SDKs, no network of any kind — the app must work in airplane mode forever, all data on-device. Follow the ios-app-factory-rules. Runnable in the iOS Simulator via Xcode; provide clear run instructions.

HARD RULE ON GAPS: Anything that would need infrastructure this project cannot provide (cloud sync, shared/community decks, a deck marketplace) must NOT be faked or stubbed. Record each honestly as a gap with a short note on what building it for real would take. Do not add placeholder UI that pretends these work.

CORE FEATURES (favor complete over broad):
1. Decks & cards: create/edit/archive decks; cards have a front, back, and optional note. Card editing must be fast and keyboard-friendly.
2. Spaced-repetition scheduling: implement the SM-2 algorithm (ease factor, interval, repetition count) with Again/Hard/Good/Easy grading. THIS IS THE HEART OF THE APP. Implement it as its own standalone, pure, tested module — provably right, not plausibly right. Unit tests MUST cover: first reviews, lapses resetting the interval, ease-factor floors, and day-boundary handling in the device's local time zone (a "day" is a calendar day).
3. Review session: shows due cards for a chosen deck (or all decks); front → tap to reveal → grade. Session summary at end (cards reviewed, again-rate, time spent). Must handle interruption gracefully — quitting mid-session loses nothing.
4. Stats: per-deck and overall — due-forecast bar chart for next 30 days, daily review-count history, and retention rate (% graded Good/Easy). Handle empty and sparse data gracefully.
5. Deck import/export: export any deck to CSV; import cards from a two-column CSV (front, back) with a preview step and per-row error reporting — never silently drop a row.
6. Review reminders: one optional LOCAL notification per day ("You have N cards due") at a user-chosen time; respect permission denial gracefully. No push, no server.

PRIORITIES (in order): (1) SM-2 module correctness above all — proven via its tests; (2) review-flow speed; (3) honest empty states. Include a "demo data" toggle in Settings that seeds two decks with a realistic review history so stats screens are never empty on first look.
```

## Final Output

**Target user & use case:** A serious, daily self-directed offline learner (300–3,000 atomic facts — language vocab, board-exam terms, cert questions), likely already an Anki/Quizlet user, who wants zero-setup, zero-account, guaranteed-offline study and will notice immediately if scheduling or stats are wrong.

**Paid value / subscription value:** Free = the entire core loop at full correctness and speed forever — SM-2 scheduling, review sessions, CSV import/export, and stats all work completely, capped only at 3 decks / 300 real (non-demo) cards and 30 days of stats history plus the 30-day forecast. Recall Plus (subscription) removes the deck/card caps, unlocks all-time stats history, and adds per-deck reminder-time customization (still 100% local notifications). A lapsed subscription never deletes or hides any deck, card, or review history the user already created — it only blocks creating new decks/cards beyond the free caps until they resubscribe or trim back down. Core correctness and review speed are never paywalled, consistent with the SM-2-then-speed-then-honesty priority order already locked.

**Core loop:** Unchanged from earlier phases — deck list with due counts → pick a deck or Study All → reveal/grade with immediate per-card persistence → truthful session summary → back to deck list. Stats, CSV, reminders, and Settings remain satellite features.

**Competitive wedge:** Deterministic, provably-correct, zero-infrastructure reliability, now extended into the monetization story — no ads, no dark patterns, no paywalled correctness or speed, ever.

**Growth angle:** Niche, not viral. CSV file portability (export/AirDrop/Files, cold-import by a study partner) is the real word-of-mouth mechanism, paired with presence in language-learning/exam-prep communities and App Store search terms like "offline flashcards no account." No referral codes or share sheets — there are no accounts to hang them on.

**Local-first & cloud-ready plan:** All card/deck/review/session state stays on-device in SwiftData with no network calls for v1. The one unavoidable exception is the App Store purchase transaction itself, which needs momentary connectivity as an OS-level StoreKit service — everything after purchase (entitlement checks, feature gating, restore) reads from the on-device transaction cache and works fully offline; this must be stated explicitly in the gap/limitations doc and verified in airplane mode (existing entitlements still work; only the purchase sheet fails gracefully without network). Any future cloud layer must be strictly additive — an optional encrypted remote mirror with immutable card-history events and a deterministic conflict policy — never a v1 dependency.

**New build-critical detail:** CSV import preview must treat "blocked by plan cap" as its own distinct, visible per-row reason (e.g., "not imported: plan limit reached"), separate from malformed-row error categories and never silently truncated — extending the existing never-silently-drop-a-row rule to the one new failure mode monetization introduces.
