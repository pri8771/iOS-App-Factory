One-sentence product promise: Pulse Relay lets a parent in a school-pickup pod broadcast an urgent same-day pickup replacement request and get one trusted pod member to lock it in in real time, with no confusion over who is actually covering it.

## Final Output

**One-sentence product promise:** Pulse Relay lets a parent in a school-pickup pod broadcast a same-day "I can't make pickup" request and guarantees exactly one trusted pod member locks it in via a server-arbitrated first-accept-wins mechanism, with no ambiguity about who's covering and no silent failure states.

**Primary user and scenario:** A parent/guardian of a child under 13 in a specific, pre-existing school-pickup pod, hit by an unplanned same-day pickup conflict, acting one-handed on a phone under real time pressure with roughly ninety seconds of attention to give the app before falling back to the class group chat.

**Core loop:** Post a same-day relay request into your pod (optional short note, no child PII) → it's visible live to pod members, who get a push notification deep-linking straight to the request card → any member can tap accept → the server arbitrates first-accept-wins → the winner sees confirmed, every other device (including a late second acceptor) sees an explicit "already covered by [pod member]" state, never silence or ambiguity → the accepter can release ("I can no longer cover this") at any point up to actual handoff, which immediately reopens the request and re-notifies the pod → if nobody accepts, the request shows a time-aware "still open — X min" state with a re-broadcast path, not a static pending spinner → marking the handoff complete generates one record that's simultaneously the internal audit log entry and the shareable, privacy-filtered relay receipt.

**Hard scope boundaries (all same tier — non-negotiable, not "cut if time is short"):**
- One app, one pod type only (school pickup) — no daycare/activity pods in v1.
- No GPS/live location or maps anywhere in v1.
- No child names, photos, or face data — requests reference "your child" generically.
- Matching only via trust-graph/pod membership (invite link or admin-issued join code) — never open/stranger matching.
- No UI implying identity verification or background-check vetting the app doesn't perform; self-vouched/pod-vetted language only.
- No in-app chat/DM thread — the request card plus one optional short note is the entire communication surface.
- No recurring or scheduled requests — same-day only.
- No payments.
- No persistent scrollable request-history feed — the only persistent surface is the audit/receipt artifact.
- Pod-creator role is deliberately thin: create pod → get join code/link → done. No admin console, no member management, no pod settings screen in v1.
- No success UI (accepted/completed/synced) without genuine backend acknowledgment.

**Measurable success criteria:**
- A real backend endpoint is deployed and reachable from the iOS client before any feature is accepted as validated.
- A fresh, zero-state account can join or create a pod via code/link with no dead end.
- Every screen in both core funnels (post request; accept/resolve/complete) shows real empty, loading, error, and success states, checkable by pulling network access mid-flow.
- Two-device race test: both devices tap accept within the same second → exactly one confirmed acceptor, one explicit "already claimed" rejection, every time.
- Request-post to push-notification-landing on a second real device verified in practice with a sub-minute target.
- Accepter release/reopen re-notifies the pod in under ~30 seconds.
- An unfulfilled request transitions to a visible, time-aware "still open" escalation state with a re-broadcast path — never silent.
- The data model supports multiple simultaneously-open requests in one pod with clear per-request identity, even though the UI may lead with a single focused card.
- Force-quit and relaunch preserves auth session and current request/feed state.
- The full loop is run start-to-finish with two genuinely separate seeded accounts in the same pod, not one account plus a mocked second party.
