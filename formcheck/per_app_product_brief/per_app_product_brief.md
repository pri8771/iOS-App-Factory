### Round 1


**Codex (Design Lead · Systems Thinker) — Round 1**

Formcheck is for a specific user: a solo home or gym bodyweight trainee doing mostly squat, push-up, and plank sets alone, with a phone on a stand and a strong preference for privacy. The app exists for users who currently get only count-only timers or generic posture advice, but want actual local feedback they can trust without relying on cloud analysis or creating accounts.

The paid reason is clear: reliable coaching in constrained environments where cloud fitness tools lose their value. Formcheck’s non-subscription version already delivers live rep counting plus one concrete form warning per set and local history, but Pro is worth paying for when users actually train repeatedly and care about iteration. Pro unlocks local, higher-value tools: exercise-specific calibration profiles (e.g., preferred stance width, depth target, rep-speed tolerance), a stricter geometry engine with confidence scoring, deeper trend summaries (quality score, warning frequency, consistency band), and enhanced review on Catalyst with richer skeleton overlays and frame stepping controls. It is functional utility, not cosmetics: users pay to reduce ambiguity and improve training quality over time.

The core loop is: open Home, run capability check (camera, Watch, HealthKit), get camera placement guidance, start a set, auto-classify the movement, run a debounced geometric rule on pose angles in near-real time, increment rep count only when the state machine deems a full rep, surface the named warning if thresholds are violated, then end the session and persist everything locally to SwiftData with explicit metadata (including whether the session is real, demo, or ended early). From there the user sees instant feedback in list/calendar history and per-exercise trends, while watch and Catalyst surfaces read from the same session store. That loop is the product, not an auxiliary feature.

The competitive wedge is not “another rep counter,” it is local explainability plus honest limitation reporting. Unlike cloud coaching apps, Formcheck never ships fake behavior in Simulator, never fabricates counts, and never hides failure modes. Unlike manual workout logs, it computes form signals directly from pose geometry. Unlike Apple’s ecosystem-first guidance, it is exercise-specific and transparent enough that users can see exactly which joint/angle rule fired and why.

The local-first behavior is absolute: no backend, no accounts, no implicit network, no silent data export. Camera capture, pose math, persistence, trend charts, and watch mirroring all work on-device. HealthKit writes are explicit and best-effort only; denied permission does not block local save. Known capability gaps are first-class states in-product, not silent fallback paths. Cloud readiness is an extension, not a dependency: future versions can add optional, user-initiated export/sync bridges using export artifacts or encrypted, opt-in cloud backup, while keeping SwiftData as the source of truth locally.

The app’s viral angle is niche-first instead of broad social growth. It is for users and communities that value trustworthy local training feedback—home trainers, recovery-focused athletes, personal trainers advising clients with privacy constraints, and small studios that prohibit cloud uploads. Growth comes from shareable, privacy-safe session packets (“coach summary bundles” exported locally) and trustworthy referral loops among people who care about form quality, not social scoreboards. The app gets sticky because repeat trainers value consistency, not gamified streaks: if warnings and counts stay stable from week to week and edge cases are disclosed honestly, users keep it because it becomes an accountable training instrument rather than another novelty.

The biggest objection to this direction is that local pose geometry can feel unreliable in real lighting or camera angles, which could cause users to lose trust fast. The detail the next phase must preserve is explicit: camera placement guidance must be built in, rep counting must use hysteresis/debounce, counts must stay non-editable, interrupted sessions must end deterministically as completed “ended early,” and every demo artifact must be tagged as non-user and excluded from real-trend utilities and any HealthKit write path.

**Claude (QA & Risk · Closer) — Round 1**

Target user, restated with teeth: this is a person training alone with a phone propped against a wall, doing squats, push-ups, or planks, who has already decided they don't want a subscription fitness app with a cloud account and a coach staring back at them through a screen. That user will forgive missed reps if the app tells them so plainly; they will not forgive being shown a fake success state or a subscription wall on the core rep counter.

Here's the paid value split I'd lock in now, because "subscription value" left vague is exactly how these projects end up bolting a paywall onto the wrong thing later: the core loop — live rep counting and the one geometric form flag per exercise, for all three exercises, plus the demo session — stays free and fully real, no crippled trial version of the thing the whole product is supposed to prove. What's genuinely worth paying for is everything downstream of a single set: unlimited session history instead of a rolling short window, full per-exercise Swift Charts trend analysis over time, the Mac Catalyst frame-by-frame clip review with skeleton overlay, the HealthKit write, and full local data export. That split isn't arbitrary — it matches the sacrifice order already locked in portfolio_selection (Catalyst first, Watch second, HealthKit third, core loop never), which means the very features this project is willing to cut under time pressure are also the features worth gating behind payment. The subscription mechanism itself needs one honest carve-out written down now, not discovered during review: StoreKit 2 purchase and entitlement refresh does require a brief network round-trip to Apple's servers — that is not the app "phoning home," it's the same rail every paid iOS app uses, and it is categorically different from the no-backend/no-accounts/no-network rule, which is about *this app* never talking to *our* servers or anyone else's about the user's workouts. Growth angle: no social feed, no leaderboard, nothing that needs a backend — but there's one legitimate, privacy-safe share mechanic worth building deliberately: a locally rendered summary card (rep count, duration, the one form note, rendered as a static image from Swift Charts/text, never a frame of the actual recorded video) that a user can push through the standard iOS share sheet if they want to. Local-first isn't a phase, it's permanent: every core feature must work identically with the network interface disabled, forever, including for paying users.
