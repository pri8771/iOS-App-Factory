## Final Output

**Architecture governing the whole spec:** Home/Capture is not a tab-embedded screen — it's a full-screen modal (`fullScreenCover`) owning its own `CaptureSessionModel`, which is the *only* writer to SwiftData and the *only* publisher to WatchConnectivity during a session. History, Charts, Session Detail, and the Watch app are pure readers of the same SwiftData store. This exists specifically to prevent the tab bar from letting a user navigate away mid-set into a state where the camera session either keeps running invisibly or gets torn down and silently drops the set — a direct instance of the priority-(c) "surfaces must never disagree" failure mode flagged in `detailed_discussion`. Because Home and the capture modal are separate hierarchies, the modal re-runs its own capability check on appear rather than trusting Home's precomputed status, closing a race where camera access changes in the gap between the two.

## Final Output

**Architecture governing the whole spec:** Home/Capture is not a tab-embedded screen — it's a full-screen modal (`fullScreenCover`) owning its own `CaptureSessionModel`, which is the *only* writer to SwiftData and the *only* publisher to WatchConnectivity during a session. History, Charts, Session Detail, and the Watch app are pure readers of the same SwiftData store. This exists specifically to prevent the tab bar from letting a user navigate away mid-set into a state where the camera session either keeps running invisibly or gets torn down and silently drops the set — a direct instance of the priority-(c) "surfaces must never disagree" failure mode flagged in `detailed_discussion`. Because Home and the capture modal are separate hierarchies, the modal re-runs its own capability check on appear rather than trusting Home's precomputed status, closing a race where camera access changes in the gap between the two.

### Navigation
- iPhone: TabView (Home, History, Settings, Known Limits). Home tab hosts landing state; capture flow presents as `fullScreenCover` (tab bar hidden). - Watch: two-screen stack, idle → in-session, no further navigation.
- Catalyst: standalone `NavigationSplitView` — sidebar session browser, detail pane with scrubber/frame-step/skeleton toggle. No capture flow exists on Catalyst.

### Screen States
- **Home**: empty/first-run (explainer + Start + Try Demo) · capability-blocked (no-hardware: explanatory icon, no remedy; denied: camera icon + Settings deep-link; restricted: lock icon, no action) · ready (last-session recap once one exists).
- **Capture modal**: ready-to-record (silhouette guide, Start disabled until aligned) · in-session (hero counter/timer/chip) · finalizing (progress ring, floors at 400ms minimum visible even if the write finishes faster).
- **Post-Set Summary**: flag-fired (amber recap) · clean (zero amber) · demo-badged variant.
- **History**: populated list/calendar with demo rows dashed+badged · empty state.
- **Session Detail**: clip-present (thumbnail + "step through frames on Mac" affordance, never a dead scrubber) · clip-absent branch.
- **Charts**: populated · under-2-sessions empty state · "demo sessions excluded" disclosure line whenever demo sessions exist.
- **Settings**: finished-feature rows render live controls; unfinished should-have rows (HealthKit, export/erase) route to Known Limits, never a dead control.
- **Known Limits**: populated, grouped by category with timestamps · honest empty state ("no capability gaps detected in this run").
- **Watch**: idle (ready / honest "iPhone unreachable" glance, never a spinner) · in-session (mirrored count+timer, haptic per rep, no navigation).
- **Catalyst**: sidebar populated · sidebar empty ("no clips recorded yet") · detail populated with scrubber/skeleton toggle.

### Motion & Haptics
- Rep pulse: spring scale 1.0→1.12→1.0, response 0.28/damping 0.55, paired with `.impact(.medium)` haptic; under Reduce Motion, degrades to an opacity pulse instead of scale.
- Amber annotation: fade in 150ms → hold ~1700ms → fade out 150ms (~2s total), `.easeInOut`; under Reduce Motion, appears/disappears without the trace-in animation but keeps full hold duration since it carries information.
- Post-Set Summary sheet: opens `.medium`, auto-snaps `.large` when a flag fired.
- Finalizing state: never resolves in under 400ms regardless of actual write speed, so it can't flash imperceptibly.

### Accessibility
- VoiceOver rep/flag events post explicit `AccessibilityNotification.Announcement` calls rather than relying on accessibilityLabel diffing, since the capture view is a largely non-interactive full-screen camera surface where label-change announcements are unreliable.
- Capability-blocked states are always icon+text, never color-only.
- Every icon-only control (classifier chip, capability remedy buttons, Catalyst toggle) has an explicit accessibilityLabel naming the action.
- RepHero has a dedicated non-standard Dynamic Type rule (see Type Scale) instead of default scaling, to avoid breaking its container.
- Optional audio cue accompanies the haptic on any fired form flag, since push-up/plank put the user's face toward the floor during the exact moment the app's value fires.

### Claude Design decision
**No external design pass.** Every token above (type, spacing, both-appearance color hex, radii, motion timing) is fully specified, so a SwiftUI builder can write `Theme.swift` directly with nothing invented. Sending this to an external design tool would only create a synchronization risk between two documents for no benefit at this stage. If App Store marketing screenshots or a launch-page mockup are wanted later, that's a reasonable separate use for Claude Design, but it does not gate the build.
