**Hard requirements**
- Native SwiftUI, iOS 17+, no third-party dependencies unless materially necessary for stability.
- Zero network calls, zero sign-in/accounts, zero analytics/telemetry/crash-reporting that leaves the device, zero iCloud/CloudKit sync — single-device local storage only (UserDefaults/FileManager/SwiftData, no CloudKit container).
- Fully playable, rules-correct Klondike: legal-move validation, multi-card run drags, win detection, multi-step undo with exact state restoration, new-game/deal with real RNG, complete stock/waste/foundation/tableau behavior.

- Tactile motion language: spring-based drag, believable flip/deal, lightweight depth/parallax, without harming frame rate or input responsiveness.
- Light and dark mode as distinct, intentional art direction (not `.colorInvert()`), both with zero hardcoded literal colors/fonts outside a central theme file.
- Haptics on move accepted / move win (and rejection if implemented) — verified via code-level check of correct trigger points, since output isn't screenshot-verifiable.
- Local stats (played, won, best time, streak) tracked **separately per draw mode**; best time shows "N/A" when the timer was off, never a fabricated value.
- Settings: draw-1 vs draw-3, card back selection (2+), timer on/off — all persisted across relaunch. Card back changes live; draw-mode changes require a new game since it alters legal deal state.
- One identifiable signature visual/interaction hook recognizable from a single static screenshot, in both appearances.

**Non-goals:** no multiplayer/social/leaderboards/friend features, no other solitaire variants (Spider, FreeCell, etc.), no IAP/ads/monetization, no accounts or sign-in, no analytics/telemetry/crash SDKs, no Game Center/achievements (touches network/sign-in), no iCloud/cross-device sync, no landscape-specific redesign (portrait-first assumed), no tutorial-first scaffolding replacing real gameplay, no placeholder card glyphs or flat templates.

**Production-readiness definition:** app launches straight into a fully playable game (never blank/wizard/placeholder); core loop (play/move/undo/new game) works with no hidden assumptions in both draw modes; win fires only on a true win; all settings and stats are functional, persisted, and correct across relaunch; both appearances render complete, themed, literal-free visuals; no placeholder screen among Game/Stats/Settings; verified no network calls escape the device.

**Decision rules for later phases**
1. Correctness, input fidelity, and deterministic local state always beat visual flourish when they compete for build/complexity budget — and the trade-off gets logged, not silently resolved.
2. Legal-move logic, persistence, and undo integrity outrank animation polish.

5. If a contract requirement isn't implemented and testable, it's out of scope and must be declared blocked — not silently dropped.
6. Prefer simpler state modeling over clever architecture whenever it makes rule validation harder to verify.
7. A visual treatment is accepted only if it reads correctly and consistently in both light and dark mode.
8. Klondike is single-deck, 7 tableau, 4 foundations, standard ascending-same-suit foundation / alternating-color-descending tableau / King-only-on-empty-column rules — locked, not re-litigated later.

**Numbered testable requirements**
1. User can launch and play a complete game with no sign-in/account/network dependency; zero network calls at runtime (verifiable offline).
2. No analytics, telemetry, or crash-reporting SDK is present or fires any event; no account-creation flow anywhere.
3. New Game initializes a legal, freshly-shuffled Klondike deal every time: stock, waste, 4 foundations, 7 tableau columns (1–7 cards), top tableau card face-up, all 52 cards in valid positions.
4. Stock, waste, foundations, and tableau columns are always visible and structurally consistent with Klondike.
5. Drag-and-drop (or tap-to-move) executes legal moves without crash, and moves a full valid stacked run together, not just the top card.
6. Illegal moves are rejected/snapped back — never silently accepted, dropped, duplicated, or vanished.
7. A legal move updates source/destination piles exactly per Klondike rules (tableau alternating-color descending, foundation ascending same-suit, King-only into empty column).
8. Win triggers only when all 52 cards are correctly on the foundations — never a placeholder or premature win state.
9. Undo reverses the last committed move and restores full prior state (piles, stock/waste position, reveal state), supporting multiple consecutive undos.
10. New Game clears progress and deals a fresh, independently-shuffled layout (real RNG, not a fixed seed).
11. Draw-1 vs draw-3 governs stock/waste behavior and takes effect at the next hand/game.
12. Settings (draw mode, card back, timer on/off) persist across relaunch.
13. Stats (played, won, best time, streak) persist locally, survive relaunch, and reflect only real play sessions — never placeholder numbers.
14. Streak increments only on validated wins and resets correctly on loss/abandon/new-game.
15. Best time shows "N/A" (never a fabricated/stale value) for sessions where the timer was off.
16. Stats/best-time are tracked separately for draw-1 vs draw-3, not combined.
17. Haptic feedback fires on accepted moves and on win; trigger points are verifiable in code.
18. Cards render an original custom rank/suit typography/iconography system across all 52 faces + back — no SF Symbols as suit glyphs, no generic flat templates — built as a systematic/generative face system for full-deck consistency.
19. Cards show visible card-stock texture/shadow/lighting suggesting a physical object, not flat vector fills.
20. Card motion (drag, deal, flip) uses spring/physics-based animation, stays jitter-free at standard fps, in both light and dark mode.
21. Light and dark mode each carry distinct, purpose-designed art direction, not a color-inversion of each other.
22. At least one signature visual/interaction hook is recognizable from a single static screenshot in either appearance.
23. All state is stored strictly on-device (no CloudKit container) and never leaves the app container.
