## Final Output

**Architecture:** SwiftUI-only view layer, iOS 17 minimum, a single `@Observable GameEngine` (main-actor-isolated, since every mutation is UI-driven) owning board/undo/timer state and instantiated once at the App root via `@Environment`, with separate `StatsLogStore` and `SettingsStore` services. Apple frameworks only — SwiftUI, Foundation, Observation, UIKit haptics (`UIImpactFeedbackGenerator`/`UINotificationFeedbackGenerator`) — no networking framework anywhere.

**Persistence:** Codable + `FileManager` in Application Support, not SwiftData (unnecessary schema/migration overhead for three small structs with no query/relationship needs) and not `UserDefaults` (narrows the required-reason API surface). Three independently persisted, independently atomic-written files — `GameSave.json`, `StatsLog.json`, `Settings.json` — each served by its own dedicated `actor` (three actors total, never one shared queue), so a slow or corrupt write to one file can never block or corrupt another. `GameSave.json` includes the undo stack itself, capped at 200 entries as a full-state log (not deltas, for determinism), with an explicit schema version so old saves can be invalidated cleanly rather than silently misread. Writes are event-driven — fired after every settling mutation (move, undo, stock draw, timer toggle, session start/end) — debounced ~300-500ms per file with a write-coalescing guard that skips a write if serialized state is unchanged, plus an unconditional non-debounced flush forced on `scenePhase` background so a worst-case jetsam kill loses at most that debounce window, never more.

**Legibility gate:** locked as a required build artifact, not a promise — a debug-reachable gallery view (or `#Preview`) rendering all 52 `CardView`s at the real computed `cardWidth` formula output, gated behind `#if DEBUG` or an internal QA toggle, used to visually confirm rank/suit legibility up through Dynamic Type `accessibility1` before the glyph shapes are treated as final.

**Testability:** `GameEngine`'s deal function takes an injectable `RandomNumberGenerator` defaulting to the system RNG — a pure testing seam for deterministic fixtures, never reachable from production/UI code. **Privacy/permissions:** zero permission usage-description keys, zero entitlements beyond the sandbox default, zero background modes. No `PrivacyInfo.xcprivacy` manifest is authored by default, since plain `FileManager` read/write doesn't trigger Apple's required-reason API rules — but if any code path ends up touching an actual required-reason API (e.g., reading a file's modification timestamp to detect a stale/corrupt save), a manifest declaring that specific usage must be authored at that point, not skipped.

**Explicit non-scope, stated deliberately rather than left implicit:** no ML/AR/CoreML/CreateML/ARKit/Vision framework anywhere in this build (forecloses a "smart hint solver" sneaking in later as disguised scope creep); no StoreKit, no payment capability, no ads.

**Dependencies:** zero third-party SwiftPM packages, enforced by an actual CI-checkable build step that fails if the project references any package beyond Apple's own frameworks — not just a policy statement.

**Architecture:** SwiftUI-only view layer, iOS 17 minimum, a single `@Observable GameEngine` (main-actor-isolated, since every mutation is UI-driven) owning board/undo/timer state and instantiated once at the App root via `@Environment`, with separate `StatsLogStore` and `SettingsStore` services.
