VISUAL DESIGN — THIS IS THE PART THAT MUST WIN AWARDS:

rounded-rectangles-with-tiny-corner-pips that every solitaire clone uses.

drag, believable flip/deal animation, subtle parallax or depth).

Also include: light/dark mode (both fully art-directed, not just inverted
colors), haptics on card moves/wins, a stats screen (games played/won,
best time, streak — all local), and a settings screen (draw-1 vs draw-3,

### Round 3


**Codex (Product Strategist · Pragmatist) — Round 3**

Claude, your `Baize & Vellum` adjustment is the right call. On the persistence failure flow, I’m shifting to a single lightweight recovery model, not a modal-heavy one. Codex’s “three-state” framing is good conceptually, but we don’t need heavy branches per screen. Let’s collapse this to one shared pattern across Game/Stats/Settings: restore attempt → success with active data / fallback to safe defaults + warning state. In practice: decode failure is never a silent zero; it shows a clear `integrityRecovered` banner/action and always lands in a truthful state. If we can’t trust data, we say that and move on with a fresh game/default settings rather than pretending. Concretely: Game uses a non-blocking banner: “Saved game not restored (file corrupt). Started fresh.” + optional “View details” and immediate Continue. ## Final Output

**Design language: Baize & Vellum.** A quiet, private card table at night or by daylight — deep green felt as the table surface, matte parchment-toned card stock with embossed bespoke rank/suit glyphs, and aged pewter reduced to small hardware accents (foundation-pile rings, card-back border piping) rather than a dominant metal surface. Rationale: felt gives an instantly-recognizable, concrete "real card table" signal that reads in a single screenshot; embossed matte vellum gives the cards real depth and physicality without a specular highlight that could wash out the rank/suit glyph at true ~45-50pt card width; and deliberately avoiding a brass/foil-forward palette sidesteps the casino/loot-box visual cliché that would otherwise undercut this app's locked positioning as the honest, non-monetized alternative to freemium solitaire apps.

**Emotional target:** the player should feel like they've sat down at a table that was made for them and is waiting patiently — competent, unhurried, and trustworthy, never gamified or anxious-making.

**Signature interaction:** the cold-launch/new-game deal. Each card leaves the deck with its own individual spring arc (not a uniform cascade), lands with a slight overshoot-and-settle that implies weight, catches a directional highlight on landing, then face-up cards get a genuine two-sided flip around a vertical axis using the real card-back and card-face art — never a cross-dissolve. This plays only on a genuinely fresh deal (first launch or explicit New Game), never on a resumed cold launch.

**Rejected default option, named concretely:** a plain `TabView` using system `List`/`Form` chrome, SF Symbol suits (♠♥♦♣) doing double duty as both corner pip and suit indicator, flat rounded-rectangle cards with a generic drop shadow on a flat system-green background, and a title/menu screen before entering the game. Concrete differences: (1) bespoke embossed rank/suit glyph system with its own typographic identity, never reused SF Symbols; (2) a custom felt table surface with real directional lighting and shadow, not a flat color fill; (3) matte vellum card stock with real texture/shadow, not a flat-fill rounded rect; (4) two genuinely art-directed lighting scenes (daylight vs. lamp-only) for light/dark, not an inverted palette; (5) no title/menu screen — the app's front door is the resume-or-deal moment itself.

**Screen inventory:** three peer tabs (Game, Stats, Settings) in one `TabView`, launching directly into Game. Game: active board with tap-to-move (single-destination auto-execute / multi-destination highlight-and-confirm / blocked-move feedback, including tapping a run's head to move the whole valid stacked run), stock draw, inline undo, win overlay, stuck overlay, shared confirmation sheet (used for both New Game and mid-game draw-mode switches), and a non-blocking recovery banner. Stats: a draw-1/draw-3 segmented toggle (a peer control, not a modal) with per-mode real empty state, populated success state, and a structurally distinct data-loss error state. Settings: draw mode (opens the shared confirm sheet if a game is in progress), card back (instant live-preview picker, no confirmation), timer on/off, the local-only data disclosure line, and a lightweight reset-to-defaults toast.

**Primary user flow:** launch → resume active board, or on a genuinely fresh deal, play the signature deal/flip → tap a card (auto-execute / highlight-and-confirm / blocked-feedback) → draw stock as needed → undo whenever → win or stuck overlay, both distinct and unmistakable → New Game re-enters the confirm-then-deal path. Switching to Stats/Settings and back never disturbs Game state.

**State model per screen:**
- *Game:* `restoring` (brief, on cold launch only) → `active` (selection / destination-highlight / blocked-feedback sub-states) → `win` / `stuck` terminal states → `pendingConfirmation` (New Game or draw-mode switch). Recovery case: if the saved game can't be trusted, the app deals fresh exactly as on first install, then layers a small dismissible banner after the deal settles: "Couldn't restore your last game — dealt a new one." No blocking modal, since there's only one honest option anyway.
- *Stats:* per draw mode — `neverPlayed` (real empty state: friendly icon + "No games played in Draw One yet, deal one to start your streak" + implicit action), `populated` (games played/won, best time or "N/A" if timer off, streak), `dataUnavailable` (structurally distinct icon/tone, explicit "your stats data couldn't be read" copy, single "Reset local stats and continue" action) — this state must never look like `neverPlayed`.
- *Settings:* live-updating controls with immediate local persistence; draw-mode changes route through the shared confirmation sheet; a reset-to-defaults toast appears only if settings persistence actually failed and defaults were substituted.

**Accessibility notes:** every card exposes an explicit VoiceOver label (rank, suit, pile, face-up/down state); suit differentiation is shape-level in the glyph family itself, never color-only; when a tap resolves to multiple legal destinations, each is exposed as a distinct VoiceOver action, not just a visual highlight; Reduce Motion gets a complete (not degraded) fallback for deal/flip/move-transit animations — settled instantly or via a much shorter linear transition.

Game: active board with tap-to-move (single-destination auto-execute / multi-destination highlight-and-confirm / blocked-move feedback, including tapping a run's head to move the whole valid stacked run), stock draw, inline undo, win overlay, stuck overlay, shared confirmation sheet (used for both New Game and mid-game draw-mode switches), and a non-blocking recovery banner. Stats: a draw-1/draw-3 segmented toggle (a peer control, not a modal) with per-mode real empty state, populated success state, and a structurally distinct data-loss error state. Settings: draw mode (opens the shared confirm sheet if a game is in progress), card back (instant live-preview picker, no confirmation), timer on/off, the local-only data disclosure line, and a lightweight reset-to-defaults toast.

**Primary user flow:** launch → resume active board, or on a genuinely fresh deal, play the signature deal/flip → tap a card (auto-execute / highlight-and-confirm / blocked-feedback) → draw stock as needed → undo whenever → win or stuck overlay, both distinct and unmistakable → New Game re-enters the confirm-then-deal path. Switching to Stats/Settings and back never disturbs Game state.

**State model per screen:**
- *Game:* `restoring` (brief, on cold launch only) → `active` (selection / destination-highlight / blocked-feedback sub-states) → `win` / `stuck` terminal states → `pendingConfirmation` (New Game or draw-mode switch). Recovery case: if the saved game can't be trusted, the app deals fresh exactly as on first install, then layers a small dismissible banner after the deal settles: "Couldn't restore your last game — dealt a new one." No blocking modal, since there's only one honest option anyway.
- *Stats:* per draw mode — `neverPlayed` (real empty state: friendly icon + "No games played in Draw One yet, deal one to start your streak" + implicit action), `populated` (games played/won, best time or "N/A" if timer off, streak), `dataUnavailable` (structurally distinct icon/tone, explicit "your stats data couldn't be read" copy, single "Reset local stats and continue" action) — this state must never look like `neverPlayed`.
- *Settings:* live-updating controls with immediate local persistence; draw-mode changes route through the shared confirmation sheet; a reset-to-defaults toast appears only if settings persistence actually failed and defaults were substituted.

**Accessibility notes:** every card exposes an explicit VoiceOver label (rank, suit, pile, face-up/down state); suit differentiation is shape-level in the glyph family itself, never color-only; when a tap resolves to multiple legal destinations, each is exposed as a distinct VoiceOver action, not just a visual highlight; Reduce Motion gets a complete (not degraded) fallback for deal/flip/move-transit animations — settled instantly or via a much shorter linear transition.
