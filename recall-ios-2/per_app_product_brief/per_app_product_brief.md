## Original Prompt

```
Build a polished, fully offline iOS spaced-repetition flashcard app called "Recall". Native Apple stack ONLY: SwiftUI + SwiftData for persistence, Swift Charts for stats. No backend, no accounts, no third-party SDKs, no network of any kind — the app must work in airplane mode forever, all data on-device. Follow the ios-app-factory-rules. Runnable in the iOS Simulator via Xcode; provide clear run instructions.

HARD RULE ON GAPS: Anything that would need infrastructure this project cannot provide (cloud sync, shared/community decks, a deck marketplace) must NOT be faked or stubbed. Record each honestly as a gap with a short note on what building it for real would take. Do not add placeholder UI that pretends these work.

CORE FEATURES (favor complete over broad):
1. Decks & cards: create/edit/archive decks; cards have a front, back, and optional note. Card editing must be fast and keyboard-friendly.
2. Spaced-repetition scheduling: implement the SM-2 algorithm (ease factor, interval, repetition count) with Again/Hard/Good/Easy grading. THIS IS THE HEART OF THE APP. Implement it as its own standalone, pure, tested module — provably right, not plausibly right. Unit tests MUST cover: first reviews, lapses resetting the interval, ease-factor floors, and day-boundary handling in the device's local time zone (a "day" is a calendar day).
3. Review session: shows due cards for a chosen deck (or all decks); front → tap to reveal → grade. Session summary at end (cards reviewed, again-rate, time spent). Must handle interruption gracefully — quitting mid-session loses nothing.
4. Stats: per-deck and overall — due-forecast bar chart for next 30 days, daily review-count history, and retention rate (% graded Good/Easy). Handle empty and sparse data gracefully.
5. Deck import/export: export any deck to CSV; import cards from a two-column CSV (front, back) with a preview step and per-row error reporting — never silently drop a row.
6. Review reminders: one optional LOCAL notification per day ("You have N cards due") at a user-chosen time; respect permission denial gracefully. No push, no server.

PRIORITIES (in order): (1) SM-2 module correctness above all — proven via its tests; (2) review-flow speed; (3) honest empty states. Include a "demo data" toggle in Settings that seeds two decks with a realistic review history so stats screens are never empty on first look.
```

**Codex (Design Lead · Systems Thinker) — Round 1**

Recall is for people who treat review as a recurring routine, not a one-off study burst: language learners, exam candidates, and professionals who memorize recurring material, and who actually review in short windows (while commuting, before bed, or in airports). The value is that Recall removes scheduling uncertainty from the loop. It tells you exactly which cards are due for today on the device, updates the moment you answer, and never asks you to trust a server, an account, or a sync status you can’t see.

The paid value has to be about speed, certainty, and time saved after the first week, not cosmetic skinning. Free can deliver the full foundation: offline data model in SwiftData, SM-2 review, immediate persistence, CSV import/export, reminders, and core charts. Pro should be a functional upgrade that helps serious users study faster and with better calibration: stronger analytics (deck-level and historical trend interpretation, missed-card diagnostics, weekly “what to trim” recommendations), review cadence hardening (exam mode presets, configurable interruption-safe session chunking), and a “review integrity pack” for power users (scheduled review plan previews, deeper retention confidence stats, and CSV validation diagnostics for big imports). The premium line is that it converts card volume and noisy study sessions into predictable, reviewable outcomes instead of feeling like a growing pile.

The product promise in use is: pick deck scope, Reveal/grade due cards with Again/Hard/Good/Easy, save immediately, and stop at any interruption point without losing anything already graded. The critical habit loop is short and repeatable; under three minutes to start, one card-at-a-time reveal-to-grade flow, then a short, honest summary. A good reminder implementation closes the loop by making the app feel reliable: one local daily notification with real permission state and a truthful “enable in Settings” path when denied.

The competitive wedge is not raw flashcard functionality. Anki, Quizlet, and similar tools are useful but imply heavier setup, account flows, or cloud assumptions and less predictability around local, timezone-sensitive due state. Recall should position itself around “provable local trust”: pure SM-2 core, on-device-only persistence, and no fake outcomes. The differentiator is not more features; it is dependable review correctness under real-world conditions like plane mode, force quits, timezone travel, and interrupted sessions.

The local-first behavior is explicit: all data, scheduling state, reminders, and stats are persisted locally, and every UI state is derivable from local store state. There is one shared due-calculation pathway fed by the same scheduling model and calendar-day semantics everywhere it appears (deck badge counts, review scope screens, reminders, charts), so no screen can lie differently about what is due. App startup must handle empty and sparse datasets with designed “you’re all set” empties, not placeholders or fake progress.

Cloud-ready extension should be additive, not a rewrite: keep the pure scheduling engine, repository boundaries, and models cleanly separated so later phases can add an optional sync adapter (iCloud or another provider) without changing the SM-2 or persistence contracts. Future sync can be opt-in and conflict-aware, but never required for v1. If sync is added later, it should still obey the same local-first invariant: work uninterrupted when offline, resolve conflicts explicitly, and never block review on network availability.

Growth should come from niche trust and portability, not broad social features. The strongest mechanism is community-to-study-circle reuse of deck CSVs that already fits the offline model: students exchange two-column decks through Notes, AirDrop, and Files, then get immediate utility through the same deterministic schedule. That creates a credible network effect in specific communities (language classrooms, exam prep cohorts, residency programs) without fake social features or account scaffolding. The keep factor is mostly behavioral trust: users stay if they believe the next-review date is right every time they return.

The decision that must survive every implementation step is this: if a review is graded, it must be safely persisted and the queue logic must remain correct to the calendar-day model under interruption, clock changes, and DST shifts. If that single invariant slips, all other differentiation collapses.

## Final Output

**Target user & paid segment:** Self-directed learners (language learners, cert/exam candidates, professionals with recurring knowledge to retain) who review in short offline bursts. Paying users are the subset whose study load has outgrown a light setup — more than a few subjects, or enough history that they want to see a trend rather than just today's count.

**Free tier (complete, not a trial):** up to 3 active (non-archived, non-demo) decks, unlimited cards per deck, full SM-2 scheduling and review flow with zero correctness difference from paid, full keyboard-fast card editing, CSV export always (data you already own is never gated), and a basic Stats view showing retention rate and today's due count.

**Paid subscription unlocks (existing features only, no new algorithms):** unlimited active decks, the 30-day forecast chart and daily-history chart, CSV import, and the daily local reminder. Four concrete unlocks, each already part of the six locked core features — nothing net-new.

**Core loop, unchanged across tiers:** scope select → load truly-due cards for today's local calendar day via the one shared due-computation path → reveal → grade → immediate persist → honest summary. Byte-for-byte identical for free and paid users, always.

**Lapsed-subscription behavior:** decks over the 3-deck cap are never deleted — they're retained in full (data and review history intact) but locked: hidden from "all decks" review scope and from creation/edit affordances, shown with a "resubscribe to review" badge. A locked deck's cards keep aging in real wall-clock time — SM-2 state is never frozen or altered by entitlement status, since freezing it would itself be a secret second scheduling behavior. Resubscribing surfaces whatever backlog has genuinely accrued.

**Demo decks:** never count toward the 3-deck cap, in either direction, enforced by the same single shared counting function used everywhere the cap is checked (creation gate, Settings' "X of 3 decks used" display) — so toggling demo data on/off never confuses or shrinks a user's real deck headroom.

**Local-first & the one network exception:** no network calls anywhere in app function; the sole exception is the StoreKit 2 purchase transaction, verified on-device via `Transaction.currentEntitlements`/`Transaction.updates`, no custom backend, no re-check required at launch — a subscription keeps working fully offline after purchase.

**Cloud-ready path (undbuilt, documented only):** SwiftData schema kept CloudKit-shaped (stable UUID identity, no force-unwrapped relationships, no CK-incompatible compound keys) as a future extension; zero sync UI or copy until a later, explicitly justified phase builds it.

**Growth mechanic:** no invented sharing/marketplace feature — CSV export/import (already required) doubles as the organic growth and migration wedge, passed via AirDrop/Files/share-sheet in language and exam-prep communities, and as an "already have cards in Anki/Quizlet/a spreadsheet? import in a minute" onboarding hook.

**Competitive wedge:** "provable local trust" — a pure, tested SM-2 module and true offline/interruption-safe operation — against Anki (setup/sync complexity), Quizlet (account/cloud-dependent), Brainscape (assumed to lack strict SM-2/interruption guarantees, still labeled ASSUMPTION per prior phase).
