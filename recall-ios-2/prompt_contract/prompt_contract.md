**Hard requirements:**
- Native iOS app "Recall": SwiftUI + SwiftData + Swift Charts only, runnable in Xcode Simulator, with explicit run instructions.
- Fully offline forever: no network calls, no backend, no accounts, no third-party SDKs, no push, no analytics/telemetry of any kind (even crash reporting would violate "no network of any kind").
- Decks: create/edit/archive; archived decks excluded from default review flow.
- Cards: front, back, optional note; keyboard-fast editing (tab/return flow, minimal taps).
- SM-2 module: standalone, pure, no SwiftData/SwiftUI imports in the core algorithm, with unit tests proving (a) first-review behavior for each grade, (b) a lapse (Again after ≥1 success) resets repetition→0 and interval→1 day with ease adjusted per formula, (c) ease-factor floor (1.3) holds under any run of Again grades, (d) due/today comparisons use local calendar-day boundaries, verified across a DST transition and around local midnight — not a rolling 24h timer.
- Review flow: due cards for one deck or all decks; front→reveal→grade; every grade persists to SwiftData immediately (not batched to session end); force-quit mid-session must leave all graded cards correctly rescheduled and ungraded cards still due — only the in-flight summary UI state may be lost.
- Session summary: accurate reviewed count, again-rate, elapsed time.
- Stats: 30-day due-forecast chart, daily review-count history, retention % (Good+Easy/graded), per-deck and overall, with real designed empty/sparse states — never fabricated data to fill a chart.

**Non-goals:** iCloud/cloud sync, accounts, shared/community decks, marketplace, analytics/telemetry/crash reporting, push notifications, widgets/watch app/Siri shortcuts, non-CSV import formats, multi-user/profiles.
