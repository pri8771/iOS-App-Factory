## Final Output

**SwiftUI architecture:** MV over ceremony-heavy MVVM — views hold `@Environment(\.modelContext)` for direct CRUD, but review-queue construction and stats aggregation go through two dedicated `@Observable` services, `DueQueryService` and `SessionEngine`, so the project's standing "one shared function, never reimplemented per screen" rule is enforced by there being exactly one type, not by convention.

**Core module boundary:** `RecallCore` ships as a real local Swift Package (not a folder group) containing the pure SM-2 engine, the shared due-computation function, and the RFC4180 CSV parser/writer, operating on plain structs with zero import of SwiftData or SwiftUI. **Data model:** grade and demo-flag fields are stored as raw `Int`/`Bool`, never Swift enums with associated values, because SwiftData's `#Predicate` macro can't reliably filter those — modeling them as enums would silently force a fallback to the already-banned post-fetch filtering. No `@Attribute(.unique)` anywhere in the schema, since it's incompatible with the CloudKit-shaped-schema requirement locked in an earlier phase.

**Persistence guarantee:** every grade write calls `context.save()` synchronously — autosave timing is not trusted for this. The force-quit/relaunch guarantee is verified by a real automated XCUITest that actually terminates and relaunches the app, not a manual checklist step.

**Permissions/privacy:** the notification-permission toggle re-polls real `UNUserNotificationCenter` state on every `scenePhase` transition to `.active`, never caching the original grant. Background Modes capability stays fully unchecked in the target — no background fetch, no silent push, nothing — since due-ness is always computed live at display time and there is nothing to keep "fresh." A `PrivacyInfo.xcprivacy` manifest declaring zero data collection is required.

**StoreKit:** stays deferred (should-have, per the earlier app_features decision), but every entitlement/cap check routes through one `EntitlementGate` service that reports unlimited today, so real billing is additive later, not a rewrite.

**CSV:** non-UTF8 files are rejected outright with one clear error rather than guessing an encoding; single-file import is hard-capped at exactly 10,000 rows with a plain-language "check you selected the right file" error above that, parsed off the main actor via streaming.

**ML/AR:** zero surface for either. No OCR, no personalization model, no CoreML, no ARKit — nothing in the locked six core features calls for it, and any future proposal along those lines is new scope requiring its own justification pass.

## Final Output

**SwiftUI architecture:** MV over ceremony-heavy MVVM — views hold `@Environment(\.modelContext)` for direct CRUD, but review-queue construction and stats aggregation go through two dedicated `@Observable` services, `DueQueryService` and `SessionEngine`, so the project's standing "one shared function, never reimplemented per screen" rule is enforced by there being exactly one type, not by convention.

**Core module boundary:** `RecallCore` ships as a real local Swift Package (not a folder group) containing the pure SM-2 engine, the shared due-computation function, and the RFC4180 CSV parser/writer, operating on plain structs with zero import of SwiftData or SwiftUI. Every function that needs "now" takes an injected `Clock` protocol (a `SystemClock` default, a `TestClock` for tests), which makes DST and calendar-day-boundary unit tests deterministic on CI regardless of machine time zone, independent of and in addition to the simulator-clock-jump integration test already locked for app-level wiring.

**Data model:** grade and demo-flag fields are stored as raw `Int`/`Bool`, never Swift enums with associated values, because SwiftData's `#Predicate` macro can't reliably filter those — modeling them as enums would silently force a fallback to the already-banned post-fetch filtering. No `@Attribute(.unique)` anywhere in the schema, since it's incompatible with the CloudKit-shaped-schema requirement locked in an earlier phase.

**Persistence guarantee:** every grade write calls `context.save()` synchronously — autosave timing is not trusted for this. The force-quit/relaunch guarantee is verified by a real automated XCUITest that actually terminates and relaunches the app, not a manual checklist step.

**Permissions/privacy:** the notification-permission toggle re-polls real `UNUserNotificationCenter` state on every `scenePhase` transition to `.active`, never caching the original grant. Background Modes capability stays fully unchecked in the target — no background fetch, no silent push, nothing — since due-ness is always computed live at display time and there is nothing to keep "fresh." A `PrivacyInfo.xcprivacy` manifest declaring zero data collection is required.

**StoreKit:** stays deferred (should-have, per the earlier app_features decision), but every entitlement/cap check routes through one `EntitlementGate` service that reports unlimited today, so real billing is additive later, not a rewrite.

**CSV:** non-UTF8 files are rejected outright with one clear error rather than guessing an encoding; single-file import is hard-capped at exactly 10,000 rows with a plain-language "check you selected the right file" error above that, parsed off the main actor via streaming.

**ML/AR:** zero surface for either. No OCR, no personalization model, no CoreML, no ARKit — nothing in the locked six core features calls for it, and any future proposal along those lines is new scope requiring its own justification pass.
