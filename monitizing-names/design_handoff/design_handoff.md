Empty: icon (rocking-cradle/gift glyph), copy "No offers yet — be the first to make your case," CTA "Make an Offer" opens OfferFormSheet. Populated: ranked OfferCards. Error (list fetch fails): icon (alert), copy "Couldn't load the offers right now," recovery "Retry" button. Reported offers simply don't render (soft-hidden, no visible "hidden" state).
- OfferFormSheet — idle: empty form. Inline-validating: red inline error per field (e.g. "Enter an amount between $1 and $10,000,000"). Content-filter-rejected: warning-triangle icon banner with the specific reason (e.g. "That phrasing got flagged — try rewording?"), field stays editable, no data lost. Valid-ready: "Continue" enabled.
- CheckoutSheet — idle: FakeCardDisplay + DemoPayButton. Processing: spinner, copy "Processing your (very real) offer…". Success: ReceiptStamp + ReorderTransitionLayer + aria-live rank announcement. Failure (persistence write fails after animation would complete): alert icon, copy "That didn't save — nothing was charged, try again?", RetryButton, entered offer data preserved so the visitor never retypes. Failure state is structurally gated behind the network response, so it can never appear after a success state has already rendered.
- Report controls — idle-flag: outlined flag icon button, `aria-label="Report this offer"`. Instant-confirmed: toast "Reported — thanks for keeping this playful." Already-reported-this-device: visually disabled chip "Reported," one-per-device cap.

**Motion & Haptics**
- Leaderboard reorder: FLIP-style position diffing (measure old → animate to new), not a naive re-rendered sort. ~420ms, `cubic-bezier(0.34,1.3,0.64,1)` spring-like ease. Visitor's own card gets a brief glow/pulse in its new slot.
- `prefers-reduced-motion`: skip the position tween and glow pulse, keep the aria-live announcement and substitute a simple opacity/highlight flash so the requirement is still met without motion.
- Sheets: slide-up with backdrop fade, ~280ms standard ease-out; focus moves to the sheet's first field on open, returns to the triggering CTA on close.
- No haptics — the Vibration API is unreliable across browsers and not worth the complexity for a novelty page; motion + aria-live carry the "moment" instead.

**Accessibility**
- Every checkout field has a real accessible label even though functionally decorative (e.g. `aria-label="Demo payment method, not a real card"`) — a screen-reader user must understand this is an intentional fake, not a broken payment form.
- Focus trapping + return-focus on both sheets.
- aria-live region fires the rank announcement the instant the reorder lands (e.g. "You're now #3 with a $500 offer for [name]"), independent of the visual motion so it fires even under reduced motion.
- Dynamic-type-equivalent: all type roles use relative units (rem) so browser text-zoom scales the whole UI without breaking layout — verified at 200% zoom on the leaderboard specifically (highest collision risk).
- localStorage-backed features (rate-limit counter, per-device report cap) degrade silently when storage is unavailable (Safari private mode, blocking extensions): UI simply omits the "already reported" disabled state and applies no client friction, rather than throwing.
- Seed listing content is present in the initial HTML response (server-rendered or statically generated), not fetched client-side after a blank first paint.

**Claude Design prompt / external-design decision:** No external design pause. The spec above (tokens, components, per-screen states, motion) is concrete enough for a builder to write a theme file and component library directly, and the app's small surface (one page, two sheets) doesn't benefit from an extra handoff seam. Screens: hero with a baked-in non-binding disclaimer, story section, ranked offer leaderboard with empty state, an offer-submission sheet, and a demo-checkout sheet with an intentionally fake, non-editable card display.
